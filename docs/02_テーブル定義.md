# 02 テーブル定義（VB原本から読み取ったもの）

VB原本には DDL（CREATE TABLE）が含まれていません。そのため、**SQL文・画面の入力桁（MaxLength）・画面の表示項目から推定**した定義です。
実DBの定義と食い違う場合は、実DBを正として [dumps/001_schema.sql](../dumps/001_schema.sql) を直します（未確認）。

VBは Npgsql 経由で PostgreSQL に接続しており、DBの種類自体は Web版と同じです。型の差は「.NET の型」と「Java の型」の間で生じます（[03](03_差異と吸収方針.md)）。

命名：VBのSQLは識別子を引用符なしで書いており、PostgreSQL では小文字に畳まれます。Web版も **小文字のスネークケース**（`m_user`、`tana_cd` など）で統一します。

## 1. テーブル一覧

| テーブル | 区分 | 役割 | 使う画面 |
| --- | --- | --- | --- |
| m_user | マスタ | ユーザー・権限 | ログイン、ユーザー管理、実績照会（結合） |
| m_products | マスタ | 商品 | 入庫、出庫、在庫検索、実績照会、在庫修正、商品メンテナンス |
| m_location | マスタ | 棚（ロケーション） | 入庫、ロケーションメンテナンス |
| t_stock | トランザクション | 在庫（商品×棚ごとの数量） | 入庫、出庫、在庫検索、在庫修正、商品メンテナンス |
| t_jisseki | トランザクション | 作業実績（入庫・出庫・修正・削除） | 実績照会（VBは読むだけ） |

## 2. m_user（ユーザー）

| 列 | 推定の型 | NULL | 内容 | 根拠 |
| --- | --- | --- | --- | --- |
| user_id | varchar(4) | 不可・主キー | ユーザーID | ログイン画面の入力が最大4桁 |
| user_name | varchar(50) | 不可 | ユーザー名 | 実績照会で表示 |
| password | varchar(14) | 不可 | パスワード（VBは平文で保存・表示） | 入力が最大14桁 |
| user_power | varchar(10) | 不可 | 権限。値は「管理者」「一般」 | メインメニューの分岐 |
| ent_date | timestamp | 不可 | 登録日時（NOW） | INSERT文 |
| edit_date | timestamp | 不可 | 更新日時（NOW） | INSERT・UPDATE文 |

## 3. m_products（商品）

| 列 | 推定の型 | NULL | 内容 | 根拠 |
| --- | --- | --- | --- | --- |
| product_cd | varchar(8) | 不可・主キー | 商品コード | 入庫は8桁で検索。画面の上限は8または9（V-12） |
| product_name | varchar(100) | 不可 | 商品名 | |
| category | varchar(20) | 不可 | カテゴリ。値は 食品／飲料／日用品／文房具／梱包資材／その他 | 画面の固定リスト |
| unit_price | integer | 不可 | 単価 | 数値としてSQLに連結 |
| case_quantity | integer | 不可 | ケース入数 | 数値としてSQLに連結 |
| ent_date | timestamp | 不可 | 登録日時 | |
| edit_date | timestamp | 不可 | 更新日時 | |

## 4. m_location（棚）

| 列 | 推定の型 | NULL | 内容 | 根拠 |
| --- | --- | --- | --- | --- |
| tana_cd | varchar(9) | 不可・主キー | 棚番 `列-連-段`（2+1+3+1+2桁） | 画面の桁数 |
| tana_retu | varchar(2) | 不可 | 列 | 入力が最大2桁 |
| tana_ren | varchar(3) | 不可 | 連 | 入力が最大3桁 |
| tana_dan | varchar(2) | 不可 | 段 | 入力が最大2桁 |
| tana_status | varchar(10) | 不可 | 状態。値は「空棚」「実棚」 | 登録時は「空棚」、削除判定で「実棚」 |
| bikou | varchar(100) | 可 | 備考 | |
| ent_date | timestamp | 不可 | 登録日時 | |
| edit_date | timestamp | 不可 | 更新日時 | |

列・連・段は数字文字列として扱われているが、桁そろえ（ゼロ埋め）の規則は原本に無い（V-13）。

## 5. t_stock（在庫）

| 列 | 推定の型 | NULL | 内容 | 根拠 |
| --- | --- | --- | --- | --- |
| stock_id | integer（自動採番） | 不可・主キー | 在庫ID | 在庫検索に表示。INSERTで指定していない |
| product_cd | varchar(8) | 不可 | 商品コード（m_products） | |
| tana_cd | varchar(9) | 不可 | 棚番（m_location） | |
| stock | integer | 不可 | 在庫数 | |
| arrival_date | timestamp | 不可 | 入庫日 | 入庫で NOW |
| ent_date | timestamp | 不可 | 登録日時 | |
| edit_date | timestamp | 不可 | 更新日時 | |

VBのコードは「1商品＝1在庫行」を前提にしています（入庫の登録・在庫修正は商品コードだけで更新）。同じ商品を別の棚に入れることは入庫画面で禁止しているため、実質1商品1棚です。

## 6. t_jisseki（作業実績）

VBは SELECT のみで、INSERT する処理が原本にありません（V-05）。列は実績照会の SELECT から読み取りました。

| 列 | 推定の型 | NULL | 内容 |
| --- | --- | --- | --- |
| jisseki_id | integer（自動採番） | 不可・主キー | **原本に無い。Web版で足す代理キー（案）** |
| sag_kbn | varchar(10) | 不可 | 作業区分。値は 入庫／出庫／修正／削除 |
| work_date | timestamp（または date） | 不可 | 作業日。型は未確認 |
| product_cd | varchar(8) | 不可 | 商品コード |
| tana_cd | varchar(9) | 不可 | 棚番 |
| quantity | integer | 不可 | 数量 |
| before_stock | integer | 不可 | 変更前在庫 |
| after_stock | integer | 不可 | 変更後在庫 |
| bikou | varchar(200) | 可 | 備考（在庫修正の理由を入れる想定） |
| user_id | varchar(4) | 不可 | 作業者（m_user） |

## 7. リレーション（SQL文の結合から）

```
m_products 1 ── * t_stock   （product_cd）
m_location 1 ── * t_stock   （tana_cd）
m_products 1 ── * t_jisseki （product_cd）
m_user     1 ── * t_jisseki （user_id）
```

VBでは外部キー制約の有無が不明です。Web版のスキーマでは、業務ルール（在庫があれば商品を削除できない等）をアプリ側で再現したうえで、データ整合のために外部キーを張る方針案とします。ただし、外部キーが VB のデータの流し込みや更新（ユーザーIDの変更、棚番の変更など）の挙動を変えるため、設計時に確認します（[04](04_移行の進め方.md)）。

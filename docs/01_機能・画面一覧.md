# 01 機能・画面一覧（VB原本の洗い出し）

イシュー #3 の「やること：VB の機能・画面・データを洗い出す」の成果物です。
VB原本（別リポジトリ・別フォルダ）を読み取り専用で参照して作成しました。原本のコードはこのリポジトリに含めていません。

- 対象：卒業課題 ver3（VB.NET / Windows Forms）。業務ロジックを持つ `.vb` は約1,800行、画面レイアウト用の `.Designer.vb` を含めて約1万行。
- 画面数：業務ロジックを持つフォームは10本（ログイン、メインメニュー、業務メニュー4、管理者メニュー4）。依頼文の「11本」との差は未確認（[04](04_移行の進め方.md) の確認事項）。
- DBアクセス：`clsDbAccess`（Npgsql 経由の PostgreSQL）。接続情報は INI ファイルから読むが、**値はこのリポジトリに書かない**。
- 以降の「列・型」は DDL が原本に無いため、SQL文と画面の入力桁から推定したものです（[02_テーブル定義.md](02_テーブル定義.md)）。

### 全画面に共通する挙動

| 挙動 | VBの実装 | Web版での扱い |
| --- | --- | --- |
| 現在時刻の表示 | タイマー（1秒）で `yyyy年MM月dd日 HH:mm:ss` を表示 | フロントの共通ヘッダーで1秒ごとに更新 |
| ログイン情報の表示 | `ID : <ID> (<権限>)` を表示。モジュール変数に保持 | サーバーのセッション（またはトークン）に保持し、共通ヘッダーに表示 |
| 戻るボタン | フォームを閉じてメインメニューを前面に出す | メインメニューへ遷移 |
| 同じ画面の重複起動の防止 | `show_window` で開いているフォームを前面に出す | ルーティングで1画面に統一（対応不要） |
| 確認ダイアログ | 登録・更新・削除時に「はい／いいえ」 | フロントの確認モーダル |
| 例外時 | `MessageBox` に例外メッセージを表示 | APIがエラー応答を返し、フロントが通知を表示 |
| カテゴリ | 「食品／飲料／日用品／文房具／梱包資材／その他」を各フォームに直書き（検索系は先頭に「すべて」） | サーバーで1か所に定義して返す |

## 2. 画面ごとの機能

### 2.1 ログイン

| 項目 | 内容 |
| --- | --- |
| 入力 | ユーザーID（最大4桁）、パスワード（最大14桁） |
| 処理 | `M_user` を全件取得し、ユーザーIDの一致とパスワードの一致を判定する。両方成立でログイン成功 |
| 成功時 | `Login_info`（`ID : xxxx (権限)`）、権限、ログインIDを保持し、メインメニューへ |
| 失敗時 | 「ユーザーIDまたはパスワードが正しくありません」を表示 |
| 注意 | IDとパスワードを別々に全行から探す実装（[03](03_差異と吸収方針.md) の V-01） |

### 2.2 メインメニュー

| 項目 | 内容 |
| --- | --- |
| 表示 | 現在時刻、ログイン状態（未ログインは「ログアウト中」） |
| ボタン | ログイン／ログアウト、入庫、出庫、在庫リスト、実績照会、在庫修正、商品メンテナンス、ロケーションメンテナンス、ユーザー管理、クイック |
| 権限制御 | 未ログイン：全業務ボタン無効。権限「一般」：入庫・出庫・在庫リスト・実績照会のみ有効。権限「管理者」：全て有効 |
| ログアウト | 確認後、ログイン情報と権限を消去し、全ボタンを無効にする（ログインIDは消去されない） |
| クイック | 認証なしで全ボタンを有効にする検証用ボタン（V-09） |

### 2.3 入庫（nyuko）

| 項目 | 内容 |
| --- | --- |
| 入力 | 商品コード（8桁で商品名を自動表示。画面上限は9桁）、棚番（列2桁・連3桁・段2桁。`列-連-段` で組み立て）、入庫数、備考 |
| 商品コード入力 | 8桁になったら `M_products` を検索し、商品名を表示。無ければ「対象の商品がありません。」 |
| 追加ボタン | 追加欄（一覧）に積む。次の検査を順に行う：①同じ商品コードが追加欄にある→「すでに追加欄に追加されています。」 ②棚番が `M_location` に無い→「入力された棚番は存在しません。」 ③`T_stock` に同じ商品があり同じ棚→「積み増しますか？」（はい＝追加、いいえ＝追加しない）。同じ商品で棚が違う→「すでに同じ商品が在庫にありますが、棚番号が異なります。」で追加しない |
| 追加欄の件数 | 追加ごとに +1、「N 件」を表示 |
| 追加欄の削除 | 選択行を削除（確認あり）。件数は選択行数に関係なく -1（V-14） |
| クリア | 入力欄を空にする |
| 登録ボタン | 確認後、追加欄の各行について、`T_stock` に商品がある→ 在庫数を加算して UPDATE。無い→ INSERT（`arrival_date`・`ent_date`・`edit_date` は NOW）。全行を1トランザクションで確定。失敗時はロールバック |
| 実績 | `T_jisseki` への書き込みは無い（V-05） |

### 2.4 出庫（syukko）

| 項目 | 内容 |
| --- | --- |
| 検索条件 | 商品コード（完全一致）、商品名（部分一致）、カテゴリ、棚の列・連・段（部分一致の組み合わせ） |
| 一覧 | 商品コード、商品名、カテゴリ、棚番、在庫数、出庫数（入力）、出庫後在庫数（在庫数－出庫数を自動計算） |
| 出庫ボタン | **未実装**（中身が空。コメントのみ） |
| 備考 | Web版で「出庫登録」を実装するときは、在庫の減算・0になったときの扱い・実績の記録を決める必要がある（[04](04_移行の進め方.md) の未決事項） |

### 2.5 在庫検索（Stock_list）

| 項目 | 内容 |
| --- | --- |
| 初期表示 | `T_stock` と `M_products` を結合して全件表示 |
| 検索条件 | 商品コード（完全一致）、商品名（部分一致）、カテゴリ、棚の列・連・段 |
| 並び順 | 商品コード順／棚番順（ラジオボタン。初期は商品コード順） |
| 一覧 | 在庫ID、商品コード、商品名、カテゴリ、棚番、在庫数、入庫日 |
| クリア | 条件を初期値に戻す（並び順は商品コード順） |

### 2.6 実績照会（jisseki）

| 項目 | 内容 |
| --- | --- |
| 初期表示 | `T_jisseki` ＋ `M_products` ＋ `M_user` を結合して全件表示 |
| 検索条件 | 期間（from〜to）、区分（すべて／入庫／出庫／修正／削除）、ユーザー名（前方一致のつもり） |
| 一覧 | 区分、作業日、商品コード、商品名、カテゴリ、棚番、数量、変更前在庫、変更後在庫、備考、ユーザー名 |
| 注意 | ユーザー名の条件が `LIKE '&名前%'` と誤記（V-06） |

### 2.7 在庫修正（stock_change）

| 項目 | 内容 |
| --- | --- |
| 検索 | 在庫検索と同じ条件（並び順なし）。表示時は自動検索しない。一覧に更新日時あり |
| 一覧クリック | 選択行の在庫ID・商品コード・商品名・棚番・在庫数を詳細欄に表示 |
| 修正ボタン | 確認後。理由が空→「理由が記載されていないので、修正できません。」／修正後在庫数<0→「…マイナスになるため、修正できません。」／=0→ `T_stock` から削除／>0→ 在庫数を更新（`edit_date`=NOW） |
| 削除ボタン | 確認後。理由が空→不可／在庫数が0でない→「在庫が存在するので削除できません。」／0→削除 |
| 注意 | 更新・削除の条件が商品コードのみ（在庫IDでない。V-08）。実績は書かない |

### 2.8 商品メンテナンス（syouhin_mente）

| 項目 | 内容 |
| --- | --- |
| 初期表示 | `M_products` 全件（商品コード、商品名、カテゴリ、単価、ケース入数） |
| 登録 | 確認後、INSERT（`ent_date`・`edit_date` は NOW） |
| 更新 | 一覧で選んだ商品を更新（条件は選択時の商品コード）。**VBのSQLは文法が壊れており実行できない**（V-07） |
| 削除 | 選択行ごとに `T_stock` の在庫が0なら削除、在庫があれば「在庫があるので削除できません。」。在庫行が無い商品は例外になる |
| クリア | 入力欄を空にする |

### 2.9 ロケーションメンテナンス（location_mente）

| 項目 | 内容 |
| --- | --- |
| 初期表示 | `M_location` 全件（棚番、列、連、段、状態、備考） |
| 登録 | 列・連・段から棚番 `列-連-段` を作り INSERT。状態は固定で「空棚」 |
| 更新 | 一覧で選んだ棚（選択時の棚番）を、棚番・列・連・段・備考で更新（状態は更新しない） |
| 削除 | 選択行ごとに、状態が「実棚」なら「実棚のため削除できません。」、それ以外は削除 |
| 一覧クリック | 先頭行がクリックしても反映されない（V-10） |

### 2.10 ユーザー管理（user_mente）

| 項目 | 内容 |
| --- | --- |
| 初期表示 | `M_user` 全件（ID、名前、パスワード、権限）。パスワードが一覧に平文で出る |
| 登録 | ID・名前・パスワード・権限（管理者／一般）を INSERT |
| 更新 | 一覧で選んだユーザー（選択時のID）を更新。IDの変更も可 |
| 削除 | 選択行ごとに：ログイン中のIDは「ログイン中のユーザーなので、削除できません。」。管理者は、管理者が2人以上のときだけ削除、でなければ「管理者が0人になるため、削除できません。」。一般は削除 |
| クリア | 入力欄を空にして再表示 |

## 4. 業務ルール一覧

| ID | ルール | 出典 |
| --- | --- | --- |
| R-01 | 棚番は `列(2桁)-連(3桁)-段(2桁)` の形式 | 入庫・ロケーション |
| R-02 | 在庫のある商品は、同じ棚にだけ積み増せる（別棚は不可） | 入庫 |
| R-03 | 存在しない棚番には入庫できない | 入庫 |
| R-04 | 入庫の追加欄に同じ商品コードは重複して入れられない | 入庫 |
| R-05 | 登録は全行を1トランザクションで行い、失敗時は全体を取り消す | 入庫・各マスタ |
| R-06 | 在庫修正は理由が必須。修正後在庫は0以上。0になれば在庫行を削除 | 在庫修正 |
| R-07 | 在庫が0でない在庫行は削除できない | 在庫修正 |
| R-08 | 在庫のある商品はマスタから削除できない | 商品メンテナンス |
| R-09 | 状態が「実棚」の棚は削除できない。新規登録の棚は「空棚」 | ロケーション |
| R-10 | ログイン中のユーザーは自分を削除できない | ユーザー管理 |
| R-11 | 管理者が0人になる削除はできない | ユーザー管理 |
| R-12 | 権限「一般」は管理者メニューを使えない | メインメニュー |
